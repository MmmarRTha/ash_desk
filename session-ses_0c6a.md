# Railway Deployment Plan (CLI-based)

Railway's **Railpack natively supports Elixir** (railpack.com/languages/elixir/). Your project's `.tool-versions` (`erlang 29.0.2`, `elixir 1.20.2-otp-29`) is exactly what it needs. Railway offers **PostgreSQL 16/17** — your `min_pg_version` requirement is satisfied.

**No Dockerfile needed.** Railpack handles the full build pipeline: installs Erlang/Elixir → `mix deps.get --only prod` → `mix assets.setup` → `mix assets.deploy` → `mix compile` → `mix release`.

Railpack then auto-sets the start command to `/app/_build/prod/rel/ash_desk/bin/ash_desk start` — we override this via the `RAILPACK_START_CMD` env var to also run migrations.

---

### Phase 0 — Install Railway CLI

```bash
curl -fsSL agents.railway.com | sh
# Alternative: npm i -g @railway/cli
```

### Phase 1 — Code Changes (local)

| # | Step | What / Why |
|---|------|-----------|
| 1 | `mix phx.gen.release` | Generates `lib/ash_desk/release.ex`, `rel/overlays/bin/migrate`, `rel/overlays/bin/server` — needed because Railpack builds a Mix release, and migrations must run at startup, not during build |
| 2 | Update sender from addresses | Change `noreply@example.com` → `System.get_env("FROM_EMAIL", "noreply@example.com")` in both sender files |

### Phase 2 — Railway Project Setup (CLI)

```bash
# Authenticate
railway login

# Create project (follow prompts to name it "ash-desk")
railway init

# Add PostgreSQL
railway add --database postgres
```

### Phase 3 — Environment Variables (CLI)

```bash
# Build env
railway variable set MIX_ENV=prod

# Database (use single quotes to prevent shell expansion)
railway variable set DATABASE_URL='${{Postgres.DATABASE_URL}}'

# Secrets (generate locally)
railway variable set SECRET_KEY_BASE=$(mix phx.gen.secret)
railway variable set TOKEN_SIGNING_SECRET=$(openssl rand -base64 48)

# Phoenix
railway variable set PHX_HOST=localhost        # temporary — update after getting domain
railway variable set PHX_SERVER=true
railway variable set ECTO_IPV6=true

# Locale (avoids latin1 encoding warning)
railway variable set LANG=en_US.UTF-8
railway variable set LC_CTYPE=en_US.UTF-8

# Override Railpack's auto start command to run migrations first
railway variable set RAILPACK_START_CMD='/app/_build/prod/rel/ash_desk/bin/migrate && /app/_build/prod/rel/ash_desk/bin/server'
```

### Phase 4 — Deploy

```bash
# Deploy (uploads local dir, Railpack builds release remotely)
railway up

# Check build & runtime logs
railway logs --build
railway logs

# Generate public domain
railway domain

# Update PHX_HOST with the generated domain
railway variable set PHX_HOST=<generated-domain>

# Redeploy with correct host
railway redeploy

# Verify in browser
railway open
```

---

### Key differences from the earlier plan

| Before | After |
|--------|-------|
| Manual `release.ex` | `mix phx.gen.release` (auto-generates everything) |
| Dashboard for env vars | `railway variable set` CLI commands |
| Dashboard for start command | `RAILPACK_START_CMD` env var (Railpack recommended) |
| GitHub push + link | `railway up` deploys directly from local dir |
| Dashboard Networking tab for domain | `railway domain` CLI command |
| `bin/ash_desk eval` + `bin/ash_desk start` | Uses `bin/migrate` + `bin/server` overlays (generated by `phx.gen.release`) |

`PHX_HOST` is set to `localhost` on first deploy to avoid the chicken-and-egg problem — update it to the real domain once `railway domain` generates one, then redeploy.
